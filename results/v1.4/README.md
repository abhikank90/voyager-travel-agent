# v1.4 Replay Benchmark Results

## Summary

v1.4 introduces deterministic replay for LLM-backed agents (intent parser and experience agent). Intent and experiences are now recorded as replay fixtures (backfilled once with `VOYAGER_REPLAY_RECORD_MISSING=1`, recorded automatically in future captures), giving replay runs with identical Round-1 conflict types and final counts.

**Key Achievement**: Two consecutive replay runs produced identical conflict detection and resolution outcomes on all 24 query pairs (12 queries × 2 modes).

## What Changed from v1.3

- **Intent parser**: Now records intent in `fixtures/live_inventory/*_intent.json`
- **Experience agent**: Now records experience list in `fixtures/live_inventory/*_experiences.json`
- **Replay anchor**: Pinned to timezone-independent anchor date for stable fixture timestamps
- **Error handling**: Research-round exceptions are now recorded in `state["errors"]` instead of being silently dropped

## Results

The v1.4 run matches v1.3 run 1 exactly (mean final conflicts 1.17, resolution rate 10%, unsatisfiable-constraint rate 67%, baseline Round-1 conflicts 1.25). What changed is that the result no longer moves between runs. The three v1.3 runs varied (unsatisfiable rate 67/58/67%, baseline Round-1 conflicts 1.25/1.25/1.33), so `benchmarks/expected_replay.json` previously held midpoints across them. It now holds the single reproducible v1.4 result:

- `unsatisfiable_constraint_rate_pct`: expected 64 → 67
- `baseline.mean_round_*_conflicts`: expected 1.28 → 1.25
- Round-1 `location_mismatch` detections: expected 17 → 16 (baseline 9 → 8)
- q0 (Greece) per-query tolerance removed

The q0 variance came from the experience list (and the parsed intent) being regenerated by the LLM on every replay run. Both `location_mismatch` and `weather_activity_mismatch` are computed from that list. The Greece flight fixture is empty, so q0 never raises `timing_inefficiency` in replay.

## Reproducibility

```bash
python3 scripts/benchmark_queries.py --mode compare --inventory replay --query-count 12
```

Run1 and Run2 produced identical conflict types and counts: `conflicts_by_round.csv` and `conflict_lifecycle.csv` match except for session IDs, and `run_summary.json` values are numerically identical (24 query pairs, mean_final_conflicts=1.17, resolution_rate=10%).

- `run2/`: Second replay run, identical to run1 except for session IDs
